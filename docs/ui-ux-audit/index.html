What needs to change

The product works.
The hierarchy needs work.

Repeated bubbles, raised cards, tinted panels and pill controls give small secondary details too much visual weight. The same visual formula appears in Home, offers, tracking, success and error screens.

Use the brand where recognition matters. Use space, type, dividers and a single blue action where the customer needs to finish a task.

Implementation sequence

Fix, simplify, verify.

Each phase has a concrete exit condition. Small routing and presentation changes are called out separately from visual styling.

PHASE 01

Usability

  • Fix the five overflowing variants.
  • Repair link targets, navigation semantics and sheet test hit targets.
  • Correct return, service-area and refund promises.
  • Surface active orders and handle overdue estimates.

Exit: no overflows, accurate state copy and actionable controls.

PHASE 02

Shared system

  • Adopt tokens and bundle production fonts.
  • Create divided rows, review summaries and a common action footer.
  • Roll out booking first, then tracking and account.
  • Remove bubbles, nested cards and repeated shadows.

Exit: consistent light/dark layouts across all screens.

PHASE 03

State polish

  • Unify loading, empty, offline and error states.
  • Keep motion short and honour reduced motion.
  • Verify keyboards, screen readers, maps and payment SDK.
  • Refresh release screenshots after implementation.

Exit: device checks complete and store images match the app.

What the local evidence does and does not cover

Baseline tests passed, but four deletion-test tap warnings weaken those interaction checks. The added 320 dp / 200% matrix has 10 failures across five variants. Native iOS navigation reached checkout without submitting an order. Real SMS, Maps SDK rendering, provider checkout, push/realtime delivery, external support actions, Android hardware and VoiceOver/TalkBack operation still need manual verification.
